⚙️ Processing Pipeline
Claim ingestion → normalisation → fingerprint → search → AI → type assignment → admin review → publish
Main Pipeline
Every claim — from any channel — flows through this pipeline exactly once. Results are cached; future identical claims are served from the database without re-processing.
1
Ingestion & Normalisation
Worker: /api/v1/check or channel webhooks
Receive raw input from any channel. Identify content types present (text, URL, image, video, audio, document). Extract text from images via OCR. Extract URLs embedded in text. Transcribe audio/video. Combine all components into a single unified claim package.
Input types handled: plain text, URL, image (OCR), video (frame extraction + transcription), audio (transcription), PDF/doc (text extraction), mixed combinations.
2
Claim Extraction
Claude API — extract specific factual assertion(s)
Pass the normalised claim package to Claude. Extract the core factual assertion(s) — the specific checkable claims, stripped of opinion or context. Generate a canonical text representation and a semantic embedding (fingerprint) for similarity matching.
3
Fingerprint & Cache Check
D1 — embedding similarity search
Search D1 for semantically similar claim fingerprints. Exact string match is not required — semantically identical claims with different wording resolve to the same record. If a match is found with a published result, serve it immediately and skip the rest of the pipeline.
✓ Cache hit
Return cached result. Record the new submission against the existing claim. Notify subscribers of any promotions since they last viewed.
→ Cache miss
No match found. Continue to Stage 4.
4
fcheck.in Database Search
D1 — full-text + embedding search across published articles
Search the fcheck.in article database for a matching original report (TYPE 1). Uses both keyword and semantic search.
✓ Match foundTYPE 1
Return full fcheck.in article. Record submission. Pipeline ends here.
→ No match
Continue to Stage 5.
5
External Fact-Checker Search
Google Fact Check Tools API + curated fact-checker crawlers
Query the Google Fact Check Tools API (indexes ClaimReview markup from 100+ publishers). Simultaneously query curated Tier 1 and Tier 2 sources. Apply country and language filters from user request. Rank results by source tier, date, and verdict confidence.
✓ Match foundTYPE 2
Return best external result with full attribution. Store result in D1. Record submission. Pipeline ends here.
→ No match
Continue to Stage 6.
6
AI Deep-Check
Claude API — source search, contradiction analysis, confidence scoring
Run a deep AI analysis. Search the open web for primary sources (research papers, government data, authoritative statements). Identify contradictions or supporting evidence. Assess source quality and quantity. Produce a confidence score (0–100) and a preliminary verdict if confidence is sufficient.
◐ Sufficient factsTYPE 3
AI has found enough to form a view. Generate preliminary response (clearly labeled) + draft article for admin queue. Store in D1. Offer "notify me when reviewed." Pipeline ends here.
○ Insufficient factsTYPE 4
Too little information to form a view. No verdict shown. Store in D1 as submitted. Offer "notify me when reviewed." Schedule re-check. Pipeline ends here.
✓
Store & Respond
D1 write + channel-specific response formatter
Persist the claim record (fingerprint, canonical text, result type, sources, confidence, submissions). Format the response for the originating channel: web JSON, WhatsApp message, Telegram reply, email, or API JSON. Increment submission count if the claim already existed.
Status Promotion Logic
Claims automatically promote upward when new information is found. Every promotion notifies all subscribed users.
TransitionTriggerHuman required?Subscriber notification
TYPE 4 → TYPE 3 Re-check job finds sufficient facts No — queues draft "An early analysis is ready for your claim"
TYPE 4 → TYPE 2 Crawler finds authenticated external report No — automatic "A verified report is ready"
TYPE 3 → TYPE 1 Admin approves draft Yes — admin approval "Full reviewed report is now available"
TYPE 3 → TYPE 2 Crawler finds external report before admin approves No — automatic "A verified report is ready" (draft stays in admin queue)
TYPE 2 → TYPE 1 fcheck.in team publishes original report Yes — admin approval "fcheck.in full report now available"
Background Jobs
Cloudflare Workers Cron Triggers. Run independently of user requests.
🔄
Re-check Job
every 6h
Re-runs AI deep-check on all TYPE 4 claims. If new sources have emerged that provide sufficient evidence, promotes to TYPE 3 and queues a draft for admin. Checks source age to avoid stale results.
🕷
Crawler Job
continuous / 15m intervals
Monitors authenticated fact-checker sources for new published reports. Matches each new report against stored claim fingerprints. Triggers TYPE 4→2 and TYPE 3→2 promotions automatically when matches are found.
📌
Trending Queue Job
every 30m
Checks non-pinned trending cards for expiry (48-hour countdown). Removes expired cards. Rotates next queued card into live position. Sends low-queue alert to admin if fewer than 5 non-pinned cards remain.
📊
Trending Candidate Job
every 1h
Surfaces trending candidates from the claim database. Ranks by: submission volume + recency + verdict weight (FALSE/MISLEADING rank higher). Only TYPE 1 and TYPE 2 claims are eligible. Populates the admin "Trending Candidates" queue.
Admin Review Flow
Human-in-the-loop step before any TYPE 1 article is published. No AI-generated report goes live without admin sign-off.
